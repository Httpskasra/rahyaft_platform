# دستیار مستندات

صفحه: `/dashboard/knowledge` — گزینه «دستیار مستندات» در منوی داشبورد.

## راه‌اندازی

در پوشه backend اجرا کنید:

```sh
npm ci
npx prisma generate
npx prisma migrate deploy
npm run build
```

سپس backend را مجدداً اجرا و frontend را build کنید. migration فقط جدول‌های جدید و نمایه جست‌وجو را اضافه می‌کند. متن مستندات و تاریخچه در PostgreSQL نگهداری می‌شوند و به volume فایل جدید نیاز نیست. فایل اصلی پس از استخراج نگهداری نمی‌شود. نسخه Node مطابق Dockerfile پروژه، Node 22، باشد.

همان تنظیمات موجود `AI_ANALYTICS_BASE_URL`، `AI_ANALYTICS_API_KEY`، `AI_ANALYTICS_MODEL`، `AI_ANALYTICS_MAX_OUTPUT_TOKENS` و `AI_ANALYTICS_TIMEOUT_MS` استفاده می‌شوند. مسیر مدل `/chat/completions` است. اگر سرویس اصلی تنظیم نشده باشد، `OLLAMA_BASE_URL` و `OLLAMA_MODEL` استفاده می‌شوند. کلید به مرورگر ارسال نمی‌شود. برای این قابلیت، provider باید Chat Completions را پشتیبانی کند؛ تنظیم `AI_ANALYTICS_API_STYLE=responses` مخصوص قابلیت قبلی analytics است.

## استفاده

۱. وارد حساب شوید و دستیار مستندات را باز کنید.
۲. فایل‌های PDF متنی، DOCX، TXT یا MD را انتخاب کنید. پیام آماده‌شدن پس از استخراج و ذخیره همه قطعه‌ها نمایش داده می‌شود.
۳. سؤال را ارسال کنید. متن بخش‌هایی که به آن‌ها ارجاع شده، زیر پاسخ بازشدنی است. برای PDF شماره صفحه و برای سایر فایل‌ها شماره بخش نمایش داده می‌شود.
۴. گفتگوها ذخیره می‌شوند؛ می‌توانید آن‌ها را باز یا حذف کنید و گفتگوی جدید بسازید.

مستندات و گفتگوهای هر حساب خصوصی هستند. تمام مسیرها JWT لازم دارند و مالکیت در backend کنترل می‌شود. حذف مستند آن را از بازیابی آینده حذف می‌کند؛ نقل‌قول‌های ذخیره‌شده در گفتگوهای قبلی باقی می‌مانند. برای پاک‌کردن آن نقل‌قول‌ها، گفتگو را نیز حذف کنید.

## روش و محدودیت‌ها

- RAG متنی: استخراج، قطعه‌بندی ۱۸۰۰ کاراکتری با هم‌پوشانی ۲۵۰ کاراکتر، یکسان‌سازی حروف فارسی، نمایه GIN و رتبه‌بندی جست‌وجوی PostgreSQL با `simple`؛ حداکثر ۸ قطعه به مدل ارسال می‌شود. این نسخه embedding یا جست‌وجوی برداری ندارد، بنابراین تطبیق مترادف‌های بدون واژه مشترک محدود است.
- دو پرسش قبلی برای تشخیص موضوع پرسش‌های پیرو استفاده می‌شوند؛ پاسخ قبلی مدل به عنوان سند استفاده نمی‌شود.
- فقط بخش‌های بازیابی‌شده و پرسش‌ها به سرویس AI تنظیم‌شده فرستاده می‌شوند. بدون نتیجه جست‌وجو، تماس مدل انجام نمی‌شود. پاسخ بدون ارجاع معتبر نمایش داده نمی‌شود؛ وجود ارجاع به تنهایی صحت همه ادعاهای مدل را تضمین نمی‌کند.
- پاسخ مدل به‌صورت JSON شامل بندهای متن و شناسه منابع دریافت می‌شود؛ ارجاع‌ها در سرور ساخته می‌شوند. خروجی نامعتبر یک‌بار در همان مهلت درخواست اصلاح می‌شود. در صورت شکست اصلاح، فقط متن واقعی حداکثر سه بخش بازیابی‌شده با برچسب روشن نمایش داده می‌شود؛ پیش‌نویس نامعتبر مدل نمایش داده نمی‌شود. خطاهای اتصال و سرویس همچنان به‌صورت خطا گزارش می‌شوند.
- هر فایل: ۱۰ MiB، حداکثر یک میلیون کاراکتر استخراج‌شده؛ PDF حداکثر ۳۰۰ صفحه. هر حساب ۱۰۰ مستند و هر گفتگو حداکثر ۵۰ نوبت پرسش و پاسخ. فایل‌های متنی باید UTF-8 باشند. فایل اسکن‌شده، تصاویر و Word قدیمی (`.doc`) پشتیبانی نمی‌شوند؛ OCR باید پیش از بارگذاری انجام شود.
- پردازش PDF و Word در پردازه جداگانه با محدودیت ۳۰ ثانیه و heap انجام می‌شود. فایل‌های تکراری برای یک کاربر پذیرفته نمی‌شوند. خطای سرویس مدل تاریخچه ناقص ایجاد نمی‌کند.

## آزمون

```sh
npm test -- --runInBand knowledge.spec.ts
node scripts/knowledge-smoke.cjs
```

آزمون smoke به دیتابیس تنظیم‌شده متصل می‌شود، fixtureها را در transaction می‌سازد و در پایان rollback می‌کند. همچنین PDF و DOCX ساختگی را استخراج می‌کند. برای آزمون اختیاری واقعی API، متغیر `KNOWLEDGE_TEST_AI=1` را تنظیم کنید؛ تنها متن ساختگی کوتاه ارسال می‌شود و یک فراخوانی مدل هزینه خواهد داشت.

برای آزمون نهایی پس از migration، یک TXT فارسی آپلود کنید؛ سؤال مرتبط و نامرتبط بپرسید، منبع را بررسی کنید، صفحه را تازه‌سازی و تاریخچه را باز کنید. با حساب دوم مطمئن شوید فایل‌ها و گفتگوهای حساب اول قابل دسترسی نیستند. PDF و DOCX واقعی محیط خود را نیز بررسی کنید.
